## 使用顺序

**手工：**先读工作流，再选局部/网络卡，确定补充内容后参照[画板样式卡](templates/board-style.md)绘图。图外保留决定记录，图稿完成后列已加入的新内容与逐锁说明，最后整理布局和审阅。教学Mermaid解释关系，不是最终画板的尺寸和位置范本。

**AI：**从[主Skill](SKILL.md)进入：整理材料 → 提案Skill确认补充及方案 → 主Skill按决定绘图与检查 → 说明Skill → 排版Skill → 成果审阅和返修 → 按需开发交接。主Skill按相对路径读取三个过程文件并接续，不依赖宿主自动扫描子技能，也不要求每步另开对话。无新增或已有明确决定时不重复询问；单独修订说明或布局时沿用有效前置材料。

绘图方式、目标画板及说明输出位置和格式分别确认；未明确时询问，明确时沿用。允许补充或授权绘图不等于采纳具体提案。未确认提案留在图外；已确认且绘入的补充保留“提案＋编号”作为来源标记。图中只放短标签和必要关系/条件，决定记录、已加入的新内容清单与亲历说明留在图外。手画不要求JSON或其他机器记录。

## 整体复制与更新

本目录是完整单元，包含主Skill、`skills/`下三个过程Skill、工作流、模板及样式图片。**整体复制或安装，不单独拆装过程目录。**其相对引用均在本包内，使用不依赖维护资料、私有飞书或作者机器。安装方法见随获取入口提供的INSTALL.md；包内执行不依赖该外层文件。

当前必需读用路径明确，但嵌套目录是否出现在某宿主的独立技能列表须另测；本包采用主入口显式读取接续即可。用户图、说明、决定和任务记录放在自己的项目，不随工具更新覆盖。Markdown是维护源，当前没有PDF；格式、链接及样式图检查不证明完整实案效果或平台兼容。
