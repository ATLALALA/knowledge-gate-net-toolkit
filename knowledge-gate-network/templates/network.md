# 知识锁网络组织卡

版本：draft-0.6 · 2026-11-24。根据实践反馈补充提案、图外说明与排版要求；修订效果待实案验证。

这张卡帮助你把多个局部发现组织成一个可检查、可修改的网络。先阅读固定说明，再复制末尾的填写区；图中已经表达清楚的内容不必抄进表格。

## 1. 什么时候使用

适用于已有若干局部构想，需要理解它们怎样接续、共用信息、分布在不同场景，或检查整体设计是否遗漏重要联系的情况。也可以从一个整体目标开始逐步建立局部单元，不要求全部局部卡先完成。

| 输入 | 本卡产出 |
| --- | --- |
| 自然语言设计、已有局部图或[局部知识锁设计卡](local-lock.md)；必要的目标、故事和游戏阶段材料 | 一份整体网络图，以及图中无法简短表达的条件、关系依据和待完善事项 |

游戏阶段只是定位已有内容的参照。网络连接要说明具体由哪项知识、线索或反馈发生联系，不用“第一关结束→第二关开始”代替这些内容。

只处理当前范围内真实存在的关系。整理区可暂存未归属内容；提交审阅的图按工作流第2.2节为每条C保留前置与中心联系，来源未定则标未知。多个独立局部及有依据的回环不要求强制连通或消除，也不要求凑齐关系类型。

## 2. 图上画什么，附注补什么

按[固定样式与排版卡](board-style.md)绘制：局部保持大兴趣点居中、小线索三角环绕、大知识/反馈在外的结构；单元间保留边界与布线通道。图只保留短标签和必要关系，完整依据、审阅问题、提案记录及逐锁亲历说明放图外。新增对象或关系先在图外提案并取得用户决定，确认后才绘入，以“提案＋稳定编号”保留补充来源；未采纳项不进入图稿。

| 内容 | 图上的表达 | 需要时才补的附注 |
| --- | --- | --- |
| 局部单元 | 用区域、标题或局部图引用标明主要兴趣点和相关内容 | 该局部在整体目标或故事中的作用 |
| 知识、线索、反馈 | 保留具体内容，必要时用同一编号引用 | 长文本、图片、游戏内来源、涉及多处时的说明 |
| 跨单元关系 | 画到实际的知识、线索或反馈，在线上写明联系和依据 | 依据较长时，以编号指向补充说明 |
| 实际访问条件 | 在受影响的入口、操作或关系旁注明条件 | 条件何时成立、影响哪些内容、仍未确定什么 |
| 场景与揭示时点 | 在对象旁写简短位置或时间标记 | 多条路径间的分布比较、提前看到某信息的影响 |
| 未定事项 | 在对应位置标“待定”或问号 | 缺口内容、影响范围、下一步需要决定什么 |

可使用中心兴趣点I、线索C、前置知识K、行动反馈F四类角色标签帮助定位。编号只服务于共享、引用和修改，不要求采用固定前缀或另建机器数据表。

图形样式沿用[局部卡](local-lock.md)：中心兴趣点与外围线索构成局部结构，知识与反馈放在外部，行动写在兴趣点通向反馈的连线上。网络组织保留这些语义；图形摆放位置、颜色或箭头朝向本身不能代替关系说明。

**前置经线索进入兴趣点。**按[工作流第2.2节](../workflow.md)保留K→C→I，禁止K→I及K→F捷径。K→C须有前置信息及用途依据；材料配置理由留在图外，不算玩家已有前置。共享K按相同内容与来源决定，不按权限等级或载体类别合并。未知前置显式占位，不计为已解决。

## 3. 三类跨锁关系

关系定义以工作流第2.2节为准。以下图式省略局部内部结构，只演示跨锁连接；实际绘图仍须保留每条C的前置和中心联系，不要求每份设计集齐三类。

| 关系 | 简短图式 | 连接时核对 |
| --- | --- | --- |
| 共用前置知识 | `K_S → C_A`、`K_S → C_B` | 是否确为同一项知识？它分别怎样支持接触或理解各锁C？ |
| 共建行动反馈 | `I_A → F_S`、`I_B → F_S`，两条线各标具体行动 | 两个行动是否共同促成同一结果？各自贡献是什么？不要把两个不同结果合为一个F |
| 反馈到前置知识的依赖 | `F_A → K_B → C_B` | F_A是否为形成K_B的必要依据？缺少它，原设计中的认识能否仍按相同依据成立？具体必要作用是什么？ |

第三类包含单条接续、一个F连向多个后锁K的分支，以及多个不同F连向同一后锁K的汇合。已有知识也可参与认识形成，写入依据；不能仅凭“有帮助”或先后关系标依赖，也不再把K→K列为独立跨锁类型。多个必要输入不代表任意一个单独充分；有替代来源时说明替代路径，不能把所有来源都误写为必需。

### 三类关系的短例

以下是彼此独立的虚构小例，只说明图式；省略的局部内容不视为已经完成设计。

- **共用前置知识：**同一份培训已教会“蓝色标记代表供水支路”（K_S），它分别帮助理解泵房标牌C_A和温室管线图C_B。共用一个K，各用途分开写，不复制两个近义K。
- **共建行动反馈：**锁A的兴趣点是接通供水，锁B的兴趣点是恢复控制电源；分别完成开阀与合闸后，才共同出现“喷淋启动”（F_S）。两条I→F分别标“打开供水阀”“合上控制电闸”，同时注明两项条件均需满足。这里是一项共同结果。
- **依赖汇合：**两次观察分别得到F_A“显示完整标记左半部”和F_B“显示同一标记右半部”。在本例只有这两个信息来源的条件下，它们共同支持后锁前置K_C“完整标记的形状”，再用于理解后锁的标记目录C_C。这里是两个不同结果，不能合并成一项共建反馈。若一个可见结果又是多个后锁K的必要依据，则画为依赖分支，分别说明依据。

教学图下方的山地观测站例完整演示单条依赖。访问条件可另标F→C，但不能替代K→C，也不算第四类认知关系。同一线索可服务多个目标，保留同一身份；同一文章中的不同信息不因共用载体就被合并。

## 4. 共同内容与独立前提怎样放

- **共享内容维护一份。**整体图中可直接画一个共同节点，也可在多个局部视图中引用同一编号。修改时检查全部引用，不重新抄写几份完整内容。
- **整体与局部共用设计内容。**网络图可以由同一图中的局部区域组成；局部卡也可以引用该区域。附注补长说明，避免另维护一张与图内容完全相同的全量节点表。
- **知识可以独立出现。**由教程、背景说明或其他范围外材料直接提供的认识，可以注明提供方式、接触位置或时点，不必补造上游知识锁。
- **独立不等于开局已知。**不知道来源或获得时点时写“待定”。如果当前局部必须依靠它，这个未定项会影响该局部是否能被理解。
- **共享不意味着相同用途。**同一认识可以一处用于发现入口，另一处用于解释现象；相应关系分别说明。若两项认识内容不同，只是相似，应分别记录。

来源标记也有两种：游戏内来源是人物、文章、场景等信息载体；设计依据是作者提供的材料、设计推断或本轮新增建议。需要追溯时分别写明，不把角色说法自动当成作者已经证实的世界事实。

## 5. 场景、条件与可行顺序

逐处检查玩家能接触什么，再讨论可能的探索顺序。可以在图旁直接回答以下问题，不必另画一张地图：

1. 相关线索、兴趣点和反馈分别位于哪里，从什么入口接触？
2. 哪项知识帮助玩家找到或理解它？哪项系统条件实际限制接触或操作？
3. 哪些信息可以提前看到，哪些直到某事件后才出现？提前看到会改变什么理解？
4. 若玩家从另一入口进入，仍有什么信息支持其推断和行动？

例如，“知道图书馆夜间开放”是一项认识；“当前处于夜间、门已解锁”是实际访问条件。可以分别标在同一入口附近，但不能以其中一项代替另一项。

可行顺序是供设计者检查的信息，不自动成为游戏的强制阅读顺序。已经明确的程序条件照实标注；只是设计者建议的先后不写成门禁。条件与知识都还不明确时，保留具体待办。

## 6. 已填教学小例：山地观测站

以下为本卡新编的教学例，所有材料和机制均属虚构，用于说明图法，未经试玩。它只覆盖“认识开门时长并尝试进入观测台入口”，不包含观测台内的后续谜题。

**设计背景。**玩家希望到观测台读取当天记录，本片段只处理进入入口。定时闸门后就是观测台入口，跨过门槛即达成本局部目标。定时闸由门外控制台开启；门侧倒计时从两侧都能看见。控制台至门口的通道畅通，路牌注明通常步行约12秒。例子中的具体时长用于说明如何写出依据，不预设实际玩家一定能及时通过。

```mermaid
flowchart LR
  K0[前置 K0：入站说明提示控制台牌可帮助判断闸门时机]
  K0 -->|按入站说明查阅控制台牌| C1
  subgraph U1[局部 U1：弄清通行窗口]
    C1[线索 C1：控制台牌写明每次重置相同时长，归零自动闭门]
    I1[兴趣点 I1：弄清开门后的可用时间]
    F1[反馈 F1：开门后显示20秒并递减，归零时门关闭]
    C1 -->|提示观察倒计时与闭门的关系| I1
    I1 -->|按下开门键，在门外观察完整倒计时| F1
  end
  K1[前置知识 K1：这台闸门每次开启提供20秒窗口]
  F1 -->|实际20秒起始值是获知窗口时长的必要依据| K1
  subgraph U2[局部 U2：进入观测台入口]
    C2[线索 C2：路牌指向门口，并标通常步行约12秒]
    I2[兴趣点 I2：穿过定时闸进入观测台入口]
    F2[反馈 F2：本次抵达门内时显示剩余8秒]
    C2 -->|提示路线，行程估计支持尝试通行| I2
    I2 -->|再次开门，沿标示路线步行穿过门口| F2
  end
  K1 -->|已有认识用于比较开门窗口与行程估计| C2
```

**前置与读法：**本虚构例明确定义入站说明K0，提示控制台牌能帮助判断闸门时机，因此引出C1；U1的F1支持形成K1，U2引用K1理解C2中的时间信息，再尝试通行。不是先知道20秒再发现20秒。设计者配置牌文与路牌的理由留在图外，不用配置连线替代来源。

本例呈现“反馈到前置知识的依赖”：牌文没有写具体秒数，F1提供实际起始值，是形成后锁前置K1的必要依据，K1再帮助理解C2。本例没有共建反馈或共用前置，不为集齐关系而补设计。F2支持当前路线可通过的认识，但本片段没有为其定义后续C用途，故写入附注，不额外绘制末端K。

| 图外补充 | 本例内容 |
| --- | --- |
| 实际条件 | 控制台可使用、定时闸有电、通道畅通；这些条件属于本例场景设定，不等于玩家知识 |
| 来源与时点 | C1在控制台旁、C2在通道入口，均可在首次开门前阅读；F1、F2分别在实际操作后出现 |
| 判断限度 | C2的12秒是行程估计；F2只支持当前条件下本次通过，不证明任意移动方式或停留都能成功 |
| 待完善 N01 | 实际试玩检查移动速度与路线辨识是否给出合理余量；若来不及，应调整路线、提示或窗口安排，而不把失败解释为玩家未理解 |

这张表只补图中未完整展开的条件和判断边界；节点内容及关系以图为准。

## 7. 整体检查与回修

绘图前由提案Skill处理是否需要补充及具体方案确认；图稿完成并核对内容后，先在图外编写“已加入的新内容”和逐锁说明，再最终排版，分别使用说明Skill和排版Skill。检查所有局部的主次、间距、共享引用和跨区布线，首次或全局布局调整查看实际全图与各局部；局部返修复查改动区域及所有相关连接。移动共享节点时检查所有用途及连接端点，不以“导入成功”代替视觉检查。教学Mermaid用于说明关系，不直接充当最终布局或长标签范本。

检查时定位具体对象或连接，写下缺什么、依据是什么、影响哪里。无需打分，也不要求所有项都适用于每个网络。

- **目标及含义：**哪些发现使玩家建立、具体化或重新理解目标？并存的追求是否各有信息和行动依据？
- **认识接续：**跨单元联系是否能指出实际知识或反馈？是否把作者知道的答案、角色陈述或推测直接当成玩家已掌握的认识？
- **前置核对：**是否有K→I/K→F捷径、缺少K来源的C或重复制造的前置？未知占位与已确认来源是否分开统计？共建同一F与多个F汇合是否区分？F→K是否确为必要依据，而非一般帮助？
- **条件与时点：**理解前提、实际访问条件和建议顺序是否分开？必要信息是否在可用时点已经能够接触？
- **共同内容：**同一知识、线索或反馈的引用是否一致？同源但不同的信息是否被误合并？
- **故事与后果：**知识的运用和行动结果怎样影响对人物、事件或目标的理解？关系是否对应实际可接触材料？
- **覆盖与未定：**当前范围中的已成文内容是否均有位置？遗漏的关系、尚无用途说明的连线和未定项是否标明影响范围？

“未安排信息”与“信息是否足以支持认识”是两个问题。前者可以从内容缺漏发现；后者仍需设计者判断，并在需要时用实际体验检验。无上游知识锁、无独立验证行动或有依据的回环不自动判错；有效图中C的前置缺失须询问并明确标未知，不能无标记地当作完整设计。

发现问题先调整相关局部及网络中的材料、连接、知识用途、行动或反馈；若确实涉及信息分布和事件时点，再回看阶段—叙事双轴安排；仍无法解决时再回到宏观处境、目标与体验。修改后沿受影响的引用检查，理由和前后版本写入项目任务记录，不在每个节点重复记录一套历史。
