# 知识锁网络：概念、目标与使用工作流

版本：draft-0.3 · 2026-11-11。配套材料见[索引](index.md)。提案与确认前置，主Skill接续提案、说明和排版三个过程Skill，修订效果待实案验证。

本文件解释这套方法为什么使用、怎样组织设计以及何时使用各张卡。具体图式、字段、填写区和教学例由[工具卡索引](templates/index.md)提供。手工设计和AI辅助使用相同的方法，阅读和使用不依赖原始论文、特定游戏或专用画板。

## 1. 知识锁网络要解决什么问题

玩家在探索中接触信息，形成对规则、人物、事件或行动后果的认识。这些认识可以使原本不清楚的行动变得可行，帮助找到新的探索方向，也可以改变对既有目标和情境的理解。

**局部知识锁**围绕一个主要兴趣点组织线索，说明玩家希望接近、理解或达成什么，哪些认识参与其中，信息怎样支持这些认识，以及行动和可见结果如何继续影响理解。“锁”可以表现为不知道去哪里、不明白怎么操作、尚未理解一段关系等，不限于一扇物理门。

**知识锁网络**把这些局部发现通过具体知识、反馈及共享信息联系起来，使设计者能够检查一处发现怎样影响另一处探索。网络保留中间的信息依据和认识变化；仅将“事件甲结束”连到“事件乙开始”，还不足以说明这种联系。

本方法服务于五个设计目标：

1. 明确玩家追求的对象及其意义，让认识与当前目标相联系。
2. 说明玩家能接触什么信息、凭什么形成推断或选择行动，显露缺失的材料和连接依据。
3. 区分行动、可见结果和结果可能支持的认识，避免把作者答案直接写成玩家已经理解。
4. 组织共享信息、后续用途、访问条件和揭示时点，使局部发现能够持续接续。
5. 将经审阅的设计交给内容制作和开发，同时保留未定事项与检验范围。

知识既可以帮助完成操作，也可以使人物处境、事件关系和行动后果变得可理解。设计时需要关注“玩家因此能做什么”以及“玩家因此怎样重新理解所处情境”，不要求每个局部另写一篇主题说明。

本包聚焦上述设计工作。已有故事、玩法和阶段规划作为输入；实际游戏系统、玩家日志界面、存档或引擎实现仍由游戏项目决定。知识节点表达预期认识，不自动转换为检测玩家是否理解的程序状态。

## 2. 理解图中的对象与关系

### 对象的区别

| 概念 | 含义 | 表达时的关键区别 |
| --- | --- | --- |
| 兴趣点 | 玩家希望接近、理解或达成的对象及其意义 | 可以是地点、现象、效果，也可以是理解本身；与所需认识分别表达 |
| 线索 | 玩家可以接触并用于辨认问题、寻找来源、形成认识或决定行动的信息 | 文章、人物和场景是载体或来源；其中具体的信息才是线索 |
| 知识 | 玩家形成或运用的具体认识 | 标明在当前情境中的用途：预期形成、作为前提使用，或由反馈支持/修订；不是权限、资源或同名数值 |
| 行动 | 玩家为追查或达成兴趣点采取的操作 | 写在兴趣点通向反馈的关系上；验证行为不是该锁的一条线索 |
| 反馈 | 行动之后玩家能看到、听到或读到的结果 | “门打开了”是结果；“玩家理解了机制”需要另说明依据，不能当作直接可见结果 |
| 实际访问条件 | 功能、资源、权限、位置、时间或事件等实际限制 | 条件本身与关于条件的认识分开；知道方法不保证当前能操作，成功操作也不证明已经理解 |
| 共享信息 | 多个用途指向同一内容 | 内容保留共同身份，各用途分别说明；同一来源里的不同信息不必合成一个节点 |

局部图以中心兴趣点和外围线索构成核心结构，知识与反馈置于外部，行动标在线上。三角是起始图式，外围顶点仍是线索；数量和连接按实际内容调整。具体画法见[局部知识锁设计卡](templates/local-lock.md)。

### 连线怎样解释

线索与兴趣点、线索之间的关系，用具体文字说明提示、告知、组成或其他实际联系。节点说明内容，连线说明用途与依据，长解释放在可定位的附注中。无需把所有关系选成固定类别。

**知识→线索需要明确区分两种用途：**

- **材料配置依据：**设计者为了支持某项认识，安排了对应的信息材料。这不表示玩家在接触材料前已经知道答案。
- **前置认识的用途：**玩家已有的认识帮助找到、取得或理解某项线索，例如知道何时来观察某种现象。

兴趣点→反馈的线上写具体行动；反馈→知识则说明结果怎样支持、补充或修订认识。图中的箭头各有用途，不能统一解释为游戏先后顺序。可能出现先尝试、再由结果形成认识的设计，也可能先比较材料形成理解，之后在另一单元运用。

跨单元联系主要通过以下四种方式表达：

| 联系 | 意义 |
| --- | --- |
| 反馈导入 | 一处可见结果支持后续认识的形成 |
| 知识依赖 | 某项认识构成理解另一项认识的前提；后者仍需相应的信息材料 |
| 知识共享 | 不同单元运用同一项认识，各用途分别说明 |
| 反馈共享 | 同一个可见结果支持多项认识或多个单元 |

这些方式用于辨认已有联系，不要求每份设计集齐四种。共享线索也可保留同一内容、分别连向不同用途；网络示意与填写方法见[网络组织卡](templates/network.md)。

### 保持表达弹性

前置知识可以由游戏直接告知或来自当前范围之外，不要求先补一个上游知识锁；独立放置也不等于玩家开局已知。某个局部可以主要通过观察、阅读和比较形成理解，不必再安排一次独立验证。草稿可以保留未定内容、回环或孤立片段；这些结构本身不构成错误，检查的是具体信息和连接是否成立。

作者的真实设定、角色的陈述、玩家当时能接触的证据应分开。反馈可能支持某种判断，不保证所有玩家都会形成该判断，也不必然证明一种解释是唯一解释。

## 3. 从现有材料选择入口

| 已有什么 | 先处理什么 | 直接进入的材料 |
| --- | --- | --- |
| 自然语言谜题、零散线索或局部构想 | 界定本次范围，提取兴趣点、信息、认识及可能的行动关系 | [局部设计卡](templates/local-lock.md)，之后联系网络 |
| 已有若干局部图 | 识别共同信息、后续用途与跨单元缺口 | [网络组织卡](templates/network.md)，需要时返回局部 |
| 已有整体网络，要检查或修改 | 读取当前版本和作者改动，定位受影响的对象及连接 | [网络组织卡](templates/network.md)及对应局部卡 |
| 已审阅设计，要交接开发 | 明确已定范围，补足操作、真实条件、系统变化和可见结果 | [开发交接附页](templates/handoff.md) |

已有宏观材料时，目标轴帮助理解追求及其含义变化，故事轴帮助定位事件及其关系，游戏阶段轴帮助定位经历和接续。它们是参照，不要求使用者为了进入本流程先补齐三套图。没有这些文件时，先用简短文字说明玩家处境、当前追求和本段在故事中的位置即可。

本文件描述设计活动的使用流程，**不规定游戏的游玩顺序，也不等于工具包构建任务的批次**。一个任务可以覆盖多个游戏阶段，设计小步骤按内容联系和工作量安排。

## 4. 整体使用流程

下列顺序帮助开始一轮设计；可以从已有材料对应的位置进入，在局部、网络和检查之间往返。目标是完成约定范围，而不是逐项填满表格。

| 环节 | 做什么 | 本环节留下什么 |
| --- | --- | --- |
| 约定范围与起点 | 明确当前要解决的设计问题、已有材料和产出范围 | 简短任务说明、原始输入或版本、当前图入口 |
| 整理材料 | 区分玩家可接触信息、作者设定、预期认识、操作和实际条件 | 可追溯的内容整理与具体未定项 |
| 补充提案与确认 | 确认是否需要补充，在图外提出具体方案；实际绘制前取得用户决定 | 可绘制的已确认内容、提案编号、未定事项及影响 |
| 展开局部 | 使用局部卡建立信息、兴趣点、知识及行动反馈的联系 | 局部图及必要附注 |
| 组织网络 | 使用网络卡处理共享、依赖、接续及信息分布 | 整体关系与条件/时点说明 |
| 检查并提出修订 | 沿局部与整体两条主线核对依据和目标联系 | 有位置、影响与建议的设计问题 |
| 编写图外说明 | 图稿内容完成后，先罗列本轮已确认且实际加入的新内容，再逐锁讲解 | 已加入的新内容清单与第二人称亲历说明 |
| 最终排版 | 说明完成后，统一大小、颜色、形状、三角结构、间距及布线，并检查实际画板 | 简洁、可辨认的当前图稿及视觉检查结果 |
| 成果审阅和返修 | 检查是否落实决定；新增设计返回绘图前的提案确认，再修改图及相关引用 | 修订稿、保留事项和简短决定记录 |
| 交接或继续迭代 | 按已确定范围交给开发，或根据新材料继续设计 | 交接附页或明确的下一工作步骤 |

### 4.1 约定范围、起点与绘图方式

先说明本次要处理的内容、预期做到什么程度，以及哪些材料需要纳入。例如“将这一段自然语言整理成完整网络并补足关键接续”，与“只检查两处共享关系”有不同的完成范围。

保存原始策划或可定位版本，指出当前有效图稿。后续改稿作为新输入记录差异，不用新结论覆盖起点。多份材料矛盾时标明差异，按作者决定采用；旧图可以作参照，但不能默默覆盖较新的明确设计。

确定手画、AI辅助或混合方式，以及目标画板/文件。**没有明确选择时先询问用户；已有明确选择时沿用。**询问应针对尚缺的方式或目标，不重复询问已确定偏好。纯手工使用可直接在现成画板参照卡片绘制；图式中的Mermaid不构成软件选择要求。

**本环节结束时：**能找到当前输入和产物位置，并知道本次设计边界。待定谜题不必在开工前全部解决；若绘图目标尚未确定，可先整理材料，实际绘图等待选择明确。

### 4.2 整理材料，提出补充并在绘图前确认

从现有材料中辨认玩家当前追求、可接触信息、作者掌握的设定、所需或可能形成的认识、操作、反馈及实际条件。先保留材料原意，不把每句文本都拆成节点，也不把每个教程步骤都强制变成知识锁。

需要追溯时分别记录两种来源：游戏内来源说明玩家从哪个人物、文章或场景接触信息；设计依据说明内容来自哪份策划、哪次决定或新增提案。

AI路径先由[提案Skill](skills/knowledge-gate-propose/SKILL.md)处理补充意愿及具体方案。尚未明确是否需要补充时先询问；用户已要求补缺或只整理时沿用。原文忠实缩写不算提案；新增线索、反馈、机制、条件、因果或跨锁关系，以及影响设计的推断应在图外提出具体提案。允许提出提案不等于采纳具体方案。

提案包含稳定编号、具体内容、拟影响位置、依据及影响和待决定事项，沿用已有N/P编号并保存在同一项目说明中。集中询问作者采纳、改写、拒绝或暂缓哪些内容；**获得明确决定之前，不生成或写入包含待定提案的图稿。**已确认且可独立成立的部分可按约定范围继续，依赖未定提案的部分保留影响说明；不将未回应解释为采纳。

确认后绘制原设计与已采纳补充，相关节点、关系、条件或图像标题以“提案＋编号”前置，例如“提案 P01 · C3”。此标记保留补充来源，不表示待定；采纳后不去掉，不改成“原文已有”。只有关系新增时只标关系。拒绝或暂缓提案留在图外记录；旧稿已画入的未确认补充先取得处理决定再返修，不能只换名称当作已确认。

已有材料中的角色说法仍是角色说法，不能因为写在策划里就当成玩家已证实的真相。条件和结果不清楚时标明影响，不自动补成硬门禁或新系统。手工作者可自行形成决定并留简短记录，无需安装Skill或额外请AI批准。

**本环节结束时：**能区分原设计、已采纳补充和未定事项，并知道本轮实际可绘制范围。已采纳但未绘制的内容尚不能计为“已加入”。

### 4.3 用局部卡展开发现与行动

使用[局部知识锁设计卡](templates/local-lock.md)，围绕主要兴趣点写清信息与认识的关系。观察、材料比较、线索联系和操作尝试都可以成为发现途径；采用当前内容实际需要的方式。

提出预期认识时，回看玩家能得到的材料是否足以支持它；从已有线索出发时，说明它能支持什么以及尚不能支持什么。涉及行动时，补上可见反馈及其认识作用，并把实际条件独立标注。认识可在当前局部形成，也可在之后运用，不强迫每个局部完成相同闭环。

初绘即遵守[画板样式卡](templates/board-style.md)：大兴趣点居中，小线索环绕成三角骨架，大知识与反馈在核心外；使用固定角色样式。画板只放节点短语、必要关系和短条件。完整来源、机制、审阅问题、提案清单与解锁说明放在图外，不能将工具卡的教学说明整段搬进画面。图上已有内容在附注中只作引用。一个目标可涉及多个场景和信息，不以固定节点数决定局部划分。

**本环节结束时：**能解释关键联系为什么存在，哪些内容尚待补充；局部图可作为整体网络的一部分，而非与它重复维护的另一套完整内容。

### 4.4 用网络卡组织共同内容与接续

使用[知识锁网络组织卡](templates/network.md)，将实际相同的知识、反馈或线索合为共同内容，各用途分别说明。多个单元“都谈到水”不一定是在运用同一认识；同一篇文章中的不同信息也可能分别服务于不同目标。

保留一处反馈、形成的认识、后续材料和行动之间真正发生的中间环节。知识依赖说明理解条件，实际权限、资源或事件限制另外标记。注明必要的场景入口、接触时点和揭示安排，检查不同可能访问顺序下仍有哪些信息支持探索。

网络组织可自下而上联系已有局部，也可从总体目标和事件关系反推需要的局部，再回到卡片细化。新增网络联系可能要求修改局部线索或反馈，允许这两者共同发展；产生新设计时返回4.2确认后再绘入，不因已经开始绘图就跳过提案步骤。

**本环节结束时：**重要跨单元联系有具体内容和依据，共享信息有共同身份。若任务要求完整整理已成文内容，核对全部内容是否有位置，不能以若干示例代替完整覆盖。

### 4.5 沿两条主线检查设计

**整体检查：网络与目标及其含义变化。**沿实际知识、线索和反馈关系追踪：哪些发现使目标具体化、增加新追求或改变原有理解，哪些认识参与行动，哪些结果又支持后续探索。参照游戏阶段定位信息何时可用，同时区别知识前提与实际访问条件。对应[网络卡的整体检查](templates/network.md)。

**局部检查：信息与行动怎样展开故事情境。**检查兴趣点为何值得追查，线索与知识的配置有何依据，玩家凭什么建立关联，行动能产生什么可见结果，这些结果又如何帮助理解人物关系和行动后果。对应[局部卡的检查问题](templates/local-lock.md)。

需要比较解释时，列出可能的解释、可行尝试及可区分结果；观察和材料比较型单元则检查各来源怎样支持推断、补充理解或呈现不同立场。不要为使用一种检查方法而改造所有谜题。

把“没有内容或用途说明”的缺漏，与“材料是否充分、解释是否合理”的判断区分。每项问题写到具体对象或关系，说明影响与补充建议。无上游知识锁、回环、未定内容或无独立验证，不自动判错。

**本环节结束时：**得到可以审阅和修改的具体问题，而非一个笼统的“图已完整”或“谜题成立”结论。

### 4.6 集中审阅，并沿受影响关系返修

**先形成图外说明，再做最终排版，最后一起提交审阅。**AI路径由[主Skill](SKILL.md)顺序读取[说明Skill](skills/knowledge-gate-explain/SKILL.md)和[排版Skill](skills/knowledge-gate-layout/SKILL.md)；手工使用也按以下内容组织，不要求安装AI。

图外说明首先列出本轮“已加入的新内容”：以绘制前版本为参照，核对用户决定与实际图稿，列出内容、提案编号或作者补充来源、实际位置及确认依据。未定、拒绝、暂缓及已采纳但未落实的项目不计入，已有内容不重复充当本轮新增。随后以单个知识锁为一段，用“你看到……你尝试……你由此可以推测……”简洁讲述当前设计中的解开过程；不为纯理解型局部硬加操作，也不将未采纳方案以条件句混进体验路径。并行内容不写成必经顺序。[说明Skill中的山地观测站示例](skills/knowledge-gate-explain/SKILL.md)提供可照用的语气与结构。

排版按样式卡统一主次、三角结构、单元边界/间距及布线，并查看实际全图和逐锁视图；移出长文字时保留图外可定位内容。不得以格式正确、没有重叠或本地导出成功代替远端视觉检查，也不得为美化图而改变设计关系。

将图稿、实际新增清单和逐锁说明一起交给作者审阅，重点检查是否落实绘图前决定及表达是否清楚。这是成果审阅，不能替代绘图前提案确认。作者进一步修改设计时记录新决定，AI新提的补充则回到提案Skill询问后再加入。

发现问题时，先调整局部和网络中的材料、联系、知识用途、行动或反馈；确实由信息分布或事件时点造成的问题，再回看外部阶段/故事安排；涉及总体目标与情境时，才进一步回到宏观设计。需要改变外部材料时提出具体修改，不把局部修订自动扩成整套策划重写。

修改前读取作者当前图稿，保留手工改动，核对这次改动涉及的共同节点和全部用途。更新图、附注及已有交接中的相关引用，检查受影响连接；用简短记录保留原因和前后版本。只读到局部图时说明覆盖范围，不能声称已经检查整个网络。

返修改变设计时，先取得需要补充部分的决定，再改图、更新实际新增清单和逐锁说明，最后调整布局；仅修改外观且说明仍有效时可沿用说明。过程技能发现未确认内容或设计问题则交回主Skill，需要提案时返回4.2，不用叙述或样式掩盖。

**本环节结束时：**现行设计与未定事项清楚，共享引用一致，作者决定可追溯。仍影响目标完成的关键缺口继续返修，或按作者明确调整的范围接续。

### 4.7 按需交接开发，保留检验边界

准备实施已审阅的内容时，使用[开发交接附页](templates/handoff.md)。引用当前图稿和具体位置，补足实际入口、操作、条件、系统变化、可见反馈和可观察的验收情境，不重新抄一份完整网络。

可以交接已经确定的部分，并说明未定内容影响哪里。局部可以交接不代表“完整整理”的任务已经完成；本次范围的完成状态另行如实记录。接手者应读取实际游戏项目后确认实现方式，本工作流不预设引擎接口或编译规则。

设计审阅、实现进度和实际验证分别记录。交互确实发生不等于玩家已经理解；玩家如何解释信息、是否能找到路径，以及工具是否帮助设计，需要在相应的实践中观察。

## 5. 一次衔接示例

沿用[网络卡中的山地观测站教学例](templates/network.md)，下面只说明材料如何经过工作流，不另建一套示例数据。此例为虚构说明，未做玩家测试。

| 工作动作 | 本例怎样处理 |
| --- | --- |
| 定范围 | 当前只处理认识定时闸的通行窗口并进入观测台入口，读取当天记录属于后续内容 |
| 整理与局部展开 | 区分控制台牌的提示、实际倒计时反馈和玩家对20秒窗口的认识；观察结果不写成程序检测到玩家已知 |
| 提案确认 | 忠实整理基础例时无需新增；若提出归零短铃，先在图外询问是否采纳，确认后才加入图稿，实际加入后才进入说明清单 |
| 网络组织 | 同一个窗口认识用于理解路牌的行程估计，并支持尝试通行；图中保留反馈、认识、材料和行动之间的连接 |
| 检查 | 约12秒的行程是估计，本次抵达时剩余8秒只支持当前情境的判断；实际余量是否合适需试玩 |
| 审阅与返修 | 若测试表明路线难辨，应定位到路线信息、操作条件或时长安排，明确修改依据并更新受影响关系 |
| 交接 | 引用已定图稿补充入口、实际计时、操作及反馈检查；不把“读过牌”或“已经理解”自动增设为交互门禁 |

工作流负责这些活动的衔接。图中文字、编号、详细条件和填写方法以相应工具卡和使用者当前设计为准。

## 6. 手工、AI辅助与共同维护

| 使用方式 | 谁做什么 | 共同要求 |
| --- | --- | --- |
| 手工 | 设计者阅读工作流，参照卡片在现成画板中画图并检查 | 保留内容、用途、依据和实际条件的区别；不要求AI或机器数据文件 |
| AI辅助整理与绘图 | AI读取当前材料，先确认补充意愿及具体提案，再依决定绘图、说明、排版；作者决定设计 | 绘图方式及目标软件未明确时询问，已有选择沿用；无法操作某画板时说明实际能力并由用户选择可行载体 |
| 混合修改 | 作者可手改，AI继续时读取当前图与附注，核对改动及受影响引用 | 不用旧输出覆盖作者修改；完整信息只有一个当前依据，局部展示使用引用 |

AI协助不改变认识、线索和条件的含义，也不替作者采纳新增设计。可以先分析缺口、准备图外具体提案，实际绘制等待用户决定；允许补缺、已有画板授权和工具规则更新都不等于采纳某项谜题提案。已明确的设计决定不反复询问。

图片可作为线索内容、表现参考或设计附注；注明其作用，不能仅因图上挂了一张图片就视为已经提供某项知识的依据。截图能呈现的范围与原画板结构可能不同，继续工作时按实际取得的材料说明检查范围。

## 7. 记录版本与接续下一轮

记录保存在使用者自己的项目中。已有任务文档时沿用，不另建统一数据库。保留足以理解决定的内容即可：

- 本轮目标、输入版本与使用的工作流/工具卡版本。
- 当前图与附注入口，实际使用了哪些材料。
- 遇到的具体问题，补充提案及作者决定。
- 关键修改及理由、影响的共同内容、前后版本。
- 尚未确定什么、哪些部分已完成或可交接、下一步做什么。

继续新对话时，提供任务入口、当前有效图/附注、原始起点与后续输入、作者决定及待处理事项。接手者先读取这些材料和所用工具版本，再继续当前工作，不根据旧聊天摘要重建另一份有效设计。

若实践发现工具本身难以使用，可以及时调整并记录所改版本与具体原因；任务回顾时再区分游戏内容未定、概念说明、模板表达、流程安排、AI执行或绘图载体的问题。一次实案发现的问题不自动证明应增加一种通用字段，也不要求为完成回顾而修改所有材料。

## 8. 怎样判断一轮工作完成

以开始时约定的范围判断：该范围内的设计内容已经处理，关键关系有依据，作者决定与未定内容可辨，当前图及引用一致，结果能供下一步使用。允许保留不阻断本轮目标的未定项；阻断目标的事项继续处理，或记录作者对范围的调整。

本包区分四种证据：文档和链接检查说明材料组织完整；设计审阅说明关系与依据经过核对；原型检查说明实际交互和反馈按设计发生；玩家体验与设计者使用记录分别帮助判断预期理解和工具使用效果。前一种结果不能代替后一种。

当前工具包为draft-0.3，各材料版本见索引；主Skill编排设计及提案、说明、排版三个过程Skill，引用同一套方法与卡片。提案确认前置和实际新增说明仍需在实案中检验，不能只凭文档更新宣布问题已解决。
